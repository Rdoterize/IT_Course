# 部署说明

## 本地演示

进入 `backend` 目录后，使用 Java 21 运行已构建的 JAR：`java -jar target/achievement-manager-1.0.0.jar --server.address=127.0.0.1 --server.port=8080`。默认使用 H2 文件数据库。数据和材料保存于 `backend/.data/`，服务重启后继续使用。

## MySQL 容器部署

`docker-compose.yml` 使用 Node.js 24、Maven / Java 21 多阶段构建，运行镜像只包含 Java 运行时、应用 JAR 和打包后的前端。MySQL 8.4 使用独立命名卷，材料保存于另一个卷，容器内以非 root 用户运行应用。

1. 复制根目录 `.env.example` 为 `.env`。
2. 配置数据库 root 密码、业务数据库密码和初始管理员密码，密码采用不同值；不要提交 `.env`。
3. 执行 `docker compose up --build -d`。
4. 使用 `docker compose logs -f app` 查看启动结果。
5. 使用自己配置的初始管理员账号登录，创建师生账号和认证指标。

MySQL 就绪后应用才启动。初次拉取镜像和安装依赖可能较慢。若宿主机 3306 已占用，可移除或修改 MySQL 的宿主端口映射；应用仍通过容器网络中的 `mysql:3306` 连接数据库。

空数据库首次启动时创建表；关闭演示种子后不会生成示例师生和成果。仅在用户表为空时创建初始管理员，已有用户时不会再初始化；管理员密码也不随环境变量变动自动重置，修改密码请使用应用中的密码管理入口。

## 公开访问

默认 Compose 只允许宿主机访问应用端口。需要公开服务时，在宿主机或可信入口配置 HTTPS 反向代理并将流量转发到 `127.0.0.1:8080`；保留同源 `/api` 与页面访问。启用 `COOKIE_SECURE=true` 后需使用 HTTPS 访问。不要直接把 MySQL 端口暴露到公网。

入口应限制上传请求体为至少 22 MB，以适应应用单文件 20 MB 限制。反向代理、证书自动续期、监控与学校统一身份认证没有包含在本项目的自动配置内，交由实际部署环境配置。

## 备份与恢复

本地 H2：先停止服务，备份整个 `backend/.data/`；恢复到相同位置后启动，核对成果条目和材料下载。应用运行时直接复制数据库文件不能保证一致性。

MySQL：在停止应用写入后，使用一致性数据库备份保存 `achievements`，同时备份 `materials-data` 卷。恢复时先恢复数据库，再将材料恢复至原存储目录，检查附件数量和下载。不要只保存 Excel 台账，它不包含全部数据库状态和材料内容。

## 升级与排障

- 更新代码后先备份数据，再运行 `docker compose up --build -d`。自动建表脚本仅负责创建不存在的表，不承担已有表结构的迁移；涉及字段变更时应编写和审查迁移脚本。
- 本地端口占用：手动更换 `java -jar` 命令的 `--server.port` 参数；Compose 可修改 `.env` 中 `APP_PORT`。
- 登录后写操作失败：检查页面与 API 是否同源、会话 Cookie 是否保留、HTTP 环境是否误启用安全 Cookie。
- 材料下载失败：检查数据库与材料是否成套恢复，以及运行账号是否可读写 `MATERIALS_DIR`。
- 初次启动缺少管理员：检查 `SEED_DEMO=false` 与 `INITIAL_ADMIN_PASSWORD` 配置，阅读启动错误；不要通过清空已有数据库重置密码。
