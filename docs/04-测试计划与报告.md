# 某专业师生业绩管理系统——测试计划与报告

版本：1.0；日期：2026 年 10 月 17 日。测试计划与实测结论分开记录；“待执行”不表示通过。后续补充结果时须保存执行环境、命令/步骤、实际输出及失败处理。

## 1. 验证目标

确认师生成果从录入、材料、审核到统计和导出形成闭环；确认多人成果按记录计数；确认普通用户不能通过编号、筛选参数、附件与导出绕过权限。数据库与材料持久化、真实 MySQL 兼容性和浏览器体验分别验收。

## 3. 执行方式

前端通过 `npm run build` 执行类型检查与生产构建；后端可用 Maven 执行构建和 JUnit 集成测试。H2 与 MySQL 的真实 HTTP 流程曾使用独立数据库与一次性验证工具运行。入口文件已按维护要求清理，测试结果与输出文件仍保留在项目中。

同时执行浏览器操作，检查表单、图表、筛选、材料下载、刷新子路由和不同角色导航。HTTP 接口通过不能替代页面交互验收。Docker 配置存在不能替代 Docker 启动与卷恢复验证。

## 7. 结论与限制

当前结论：**首版前后端已完成集成打包并启动，后端 9 项自动化及 H2 / MySQL 8.0.46 两库各 12 组 HTTP 核心流程通过，浏览器录入到审核归档的核心交互已通过。** 内嵌浏览器下载落盘、容器/MySQL 8.4、备份恢复和上表未覆盖边界仍保留为未完成验证。一次性启动、构建和 HTTP 验证入口已按用户要求清理，历史结果保留。

已知规模限制：当前查询采用应用内筛选和逐项关联查询，导出在内存中生成，限制为单次 10000 项成果和 100 MB 附件。两项并发正确性测试不代表高并发吞吐能力已验收。不在本次测试承诺范围的还有渗透测试、长期稳定性、自动备份、校园网 SSO 和认证政策适配；实际生产使用应按学校规范补充验证。
