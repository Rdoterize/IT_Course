# 某专业师生业绩管理系统——AI 辅助开发记录

日期：2026 年 10 月 17 日。本记录说明本次对话中可确认的 AI 工作，不虚构小组成员、人工工作时长、测试截图或尚未发生的验证结论。实际学生贡献由小组补充。

## 1. 使用目标

利用 AI 加快需求结构化、技术路线确定、接口与数据库设计、代码框架、前后端实现、文档和验证方案，满足师生成果日常管理及认证材料整理需求。用户先要求确定技术栈和路线，随后选择 Java + Vue 并要求尽快完成。

## 3. 关键判断与修正

1. 共同成果采用一条成果记录关联多人，避免通过为每位成员复制成果造成专业总数膨胀。系统仍不自动识别不同编号下的重复成果。
2. 指导业绩通过参与角色关联到学生成果，不创建一套重复数据。
3. 文件实际内容与扩展名共同校验，材料目录不作为静态目录公开，下载复用成果权限。
4. 快速交付采用 JSON 文本保存分类扩展，未将最初设想的多张分类扩展表写成已实现结构。
5. 首版明确为自然年、单专业、一级审核；学年历史归属、全文版本、批量导入、自动达成度留作后续，不把愿景混入实际功能。
6. 提供测试计划后实际运行构建与业务验证：后端 9 项通过，H2 和 MySQL 8.0.46 两个独立库真实 HTTP 验证各 12 组通过，并保存 JSON、Excel 和材料包。打包后实际浏览器完成学生录入、上传、提交、管理员审核和归档，保存真实界面截图；下载事件未捕获、Docker/MySQL 8.4 和恢复等未测项如实保留，未写成“全部通过”。

## 4. 可复用提示示例

以下为小组后续可采用的提示范例，用于复现方法，不标注为本次逐字历史记录。

> 将师生成果管理需求拆成角色、用例、状态机、数据范围和验收标准。特别说明共同成果和指导关系的统计去重规则，区分首版与后续功能。

> 根据已有接口契约检查成果详情、附件下载和材料包导出是否复用数据权限，列出普通用户尝试越权的负向测试。

> 对比数据库建表脚本与设计报告，找出文档承诺但代码未实现的内容；不要虚构测试结果，未执行的标为待验证。

## 5. 责任与真实性

AI 产物需由使用者审查。成果真实性、学校政策、认证结论及学生个人贡献不能由 AI 推断。演示数据均为虚构，不能替代真实业绩材料。

提交课程报告前，小组应补充：真实姓名及分工、实际运行环境、测试输出、问题及回归记录、真实页面截图（如课程要求）、人工改进内容与引用来源。不得将自动生成记录当作已经完成的人工验证。
